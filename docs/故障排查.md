# 故障排查

**版本：V0.1** · **编制日期：2026-09-30**
**适用范围：设备会话、项目权限、限流与实时事件。SSH、网络、防火墙、首次连接类问题见根目录 [README.md](../README.md) 第 7 节。**

## 1. 401 / 403 / 429 怎么区分

| 状态码 | 含义 | 处理 |
|---|---|---|
| 401 `unauthorized` | Bearer token 缺失、过期或已撤销。access token 只有 15 分钟，过期属正常现象 | App 自动用 refresh token 换新并重试一次；refresh 也返回 401（30 天过期，或会话/设备被撤销）时回到绑定页重新绑定 |
| 403 `forbidden` | 已认证但权限不足：项目角色不够（如 viewer 提交任务），或迁移窗口内用会话 Token 访问文件/git/终端/IDE 接口 | 让 owner 在“项目成员”中提升角色；宿主能力接口见第 4 节 |
| 429 `rate_limited` | 触发限流 | 见第 2 节 |

注意：连续认证失败本身计入限流（30 次/10 分钟，按客户端 IP），反复用错误 token 重试会让 401 升级为 429，进一步扩大影响。

## 2. 限流与退避

| 限流项 | 阈值 | 窗口 |
|---|---|---|
| 绑定 `POST /v1/auth/link` | 5 次 | 10 分钟 |
| 刷新 `POST /v1/auth/refresh` | 60 次 | 10 分钟 |
| 认证失败 | 30 次 | 10 分钟 |
| SSE 事件流 | 每设备最多 5 条并发 | 超限即 429 |

均为按客户端 IP 的固定窗口。经 SSH 隧道访问时所有设备的来源地址都是 127.0.0.1，**多设备共享同一额度**。收到 429 后停止重试，等待窗口滑过（最长 10 分钟），不要提高重试频率。SSE 429 说明存在未关闭的旧连接，先关闭闲置的事件流再重试。

## 3. 会话过期与重新绑定（Android）

- **access token 过期**：App 收到 401 后自动 refresh 并重试一次，用户无感知。
- **refresh token 失效**（30 天过期、会话被退出、设备被撤销）：refresh 返回 401，App 清理本地会话并回到“绑定模型”页，需重新提交 API Key 绑定。重新绑定的设备默认为 viewer（除非是首台设备）；若旧设备记录仍在，可由 owner 在设备管理中撤销。
- **手机丢失**：在任一 owner 设备上或用本地管理员 Token 调 `DELETE /v1/auth/devices/:id` 撤销该设备，其全部会话与内存中的 access token 立即失效。
- refresh token 保存在 Android Keystore；卸载 App 或清除应用数据后凭据丢失，需要重新绑定。API Key 不保存在手机上，重新绑定需要再次输入。

## 4. 迁移窗口内“终端/文件/Git/IDE 不可用”

文件、Git、终端和完整 IDE 接口在迁移窗口内只接受旧静态 Token（本地管理员，D-13）：

- 用设备会话登录时这些接口返回 403，终端标签页不可用——属预期行为，不是故障。
- 需要这些能力时使用旧流程连接（App 经 SSH 读取 `auth-token` 的“连接已有服务”）。
- WebSocket 终端用旧 Token 认证（Authorization 头或 `?token=` 查询参数），不受设备会话支持。
- 窗口结束条件与后续鉴权方案见 [决策记录](决策记录.md) D-13。

## 5. 事件流与游标

- **轮询**：`GET /v1/events?after=<cursor>&projectId=&limit=`。`after` 为非负整数（事件 id，即游标）；`limit` 默认 200、上限 1000；响应含 `cursor`，下次轮询用它做 `after`。
- **SSE**：`GET /v1/events/stream?projectId=&after=`。连接后先回放游标之后的事件，再实时推送增量；断线重连用 `Last-Event-ID` 头或 `?after=` 带上最后收到的游标，不重不漏。每 15 秒收到一行 `: heartbeat` 注释是正常保活，不是数据。
- 会话 Token 不指定 `projectId` 时只返回已授权项目的事件；角色变化后事件范围随之变化。
- 游标非法（非整数、负数）返回 400；无法确认游标时用 `after=0` 全量重拉即可恢复。
- 每设备最多 5 条并发 SSE 流；页面反复进出导致连接未释放会触发 429，稍后重试并确保旧页面已关闭。

## 6. 日志与敏感信息

- 服务日志即启动窗口的 stdout（`server/scripts/start-windows.ps1` 启动的 PowerShell 窗口）；没有单独的日志文件，需要留存时自行重定向输出。
- **保证**：模型 API Key 与 refresh token 明文不会出现在日志、审计事件、SSE 事件或错误文本中——Key 只在绑定时写入受保护存储（`secrets.json`），refresh token 数据库只存 sha256 哈希，错误文本经脱敏处理。审计事件只记录设备、角色与动作。
- **例外注意**：启动日志会打印旧静态访问令牌（同 `auth-token` 文件内容），分享启动截图或日志前先遮蔽该值。
- 数据目录 `%USERPROFILE%\.sscode` 下的 `sscode.db` 含有任务内容与事件记录，文件本身不加密，按敏感文件对待。
