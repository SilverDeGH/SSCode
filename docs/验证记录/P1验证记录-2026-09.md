## 2. 逐项验证结果

- **未覆盖**：密码认证、加密私钥口令、RSA 私钥。待后续补测。

### P1-02 回环地址 + SSH 隧道 — 通过

### P1-04 用户目录安装与用户级服务 — 通过

- Node.js 经 npmmirror 二进制镜像安装至 `~/.local/opt`（nodejs.org 直连不可达，镜像可用）。
- systemd 用户服务 `sscode-server.service`：enable --now 成功，Linger=yes 支持登出后驻留与开机自启。
- 全程无 sudo。

### P1-05 真实模型工具调用 — 通过（单一接口）

- **重要发现**：`sk-sp-` 前缀为百炼套餐专属 Key（Coding Plan / Token Plan），与通用 Key（`sk-`）及 Base URL **完全隔离**，混用返回 `invalid_api_key`。Token Plan 专属端点为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`（来源：raw/model-api-reference/preparations/error-code.md、token-plan-team-quickstart.md）。App 的模型配置流程必须允许用户自定义 Base URL，不能写死通用地址。
- 直接 curl：kimi-k2.7-code 正确返回 `tool_calls`（含 reasoning_content 扩展字段，适配器已兼容忽略）。
- 经服务端 `POST /v1/models/:id/test`：`{"ok":true,"detail":"连接正常，模型 kimi-k2.7-code 可解析出工具调用"}`。
- **未覆盖**：第二种独立兼容接口（验收 5 要求两个接口；当前仅一个服务商账号，qwen/deepseek 同端点未计入）。

### P1-06 断线续跑与重连恢复 — 通过

- 提交真实任务（改 calc.py、建 test_calc.py、跑测试、改 README）后立即断开 SSH 隧道模拟手机离线。
- 90 秒后服务器侧核查：任务 **completed**，7 个工具调用全部 done，测试真实执行通过，总结完整。
- 重建隧道后：任务状态/工具调用可读；事件流 21 条经 `?after=<cursor>` 增量补发；`/changes` 变更列表正确（2 modified + 1 created）。
- token 用量事件真实记录（promptTokens 3852 等）。
- **服务重启场景**：任务执行中 `systemctl --user restart` → 任务自动转 `interrupted` 不静默重放；同 clientRequestId 重复提交返回 `deduplicated:true` 且不新建任务；`/resume` 确认后重新排队并完成。

### P1-08 快照与撤销保护 — 通过

- 任务完成后人工向 calc.py 追加一行修改，再执行 undo：
  - README.md → `restored`（恢复任务前内容，实测一致）；
  - calc.py → `conflict`（人工后续修改未被覆盖，AI 与人工改动均保留）；
  - test_calc.py → `deleted`（任务新建文件被清理）；
  - 任务前已有的 notes.txt 未受影响。
- caveats 正确声明命令副作用不在撤销范围。
