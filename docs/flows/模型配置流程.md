## 1. 主流程

```mermaid
flowchart TD
    A[设置 → 模型配置] --> B{选择接入方式}
    B -->|Kimi 预设| C[预填 API 地址与模型清单<br/>只需输入 API Key]
    B -->|OpenAI 兼容自定义| D[输入 API 地址、API Key、模型名称]
    C --> E[连接测试]
    D --> E
    E --> F{连接结果}
    F -->|失败| F1[明确原因：网络不可达/<br/>地址错误/认证失败/Key 无效<br/>提供修改重试]
    F1 --> E
    F -->|成功| G[工具调用能力测试<br/>发起一次真实 function/tool calling]
    G --> H{工具调用支持?}
    H -->|不支持| H1[明确提示：该模型/接口不支持所需工具调用<br/>不宣称可执行完整 AI 编程任务<br/>允许保存但标记能力受限]
    H -->|支持| I[测试通过]
    I --> J[保存配置]
    J --> J1[API Key 发送至服务器专用位置存储<br/>限制文件权限，不进仓库/日志/诊断包]
    J1 --> K{设为默认模型?}
    K -->|是| L[更新全局默认]
    K -->|否| M[仅保存]
    L & M --> N[返回模型列表<br/>显示各配置测试状态]
```

## 3. 关键设计要点

1. **能力测试先于可用声明**：必须通过真实工具调用测试才标记"可用于 AI 编程"（REQ-AI-06，对应 AC-5）。
2. **Key 的流向**：手机输入 → SSH 隧道 → 服务器专用存储（权限 600）；手机本地不留存模型 Key；支持更新与删除（REQ-SEC-03、05）。
3. **协议差异记录**：P1 需实测 Kimi 与另一兼容服务的流式输出、工具调用格式、错误结构差异并记录（REQ-AI-06），适配范围以实测为准。
4. **执行中修改配置**：仅影响后续任务，避免运行中任务行为漂移（REQ-AI-05）。
5. **失败处理**：认证失败/额度不足在任务执行中触发时，任务转"受阻"并指向模型配置修正入口（REQ-AI-22）。
