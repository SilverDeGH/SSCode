# 隐私与威胁模型（API Key 会话共享与远程任务）

**版本：V0.1** · **编制日期：2026-09-30**
**对应计划：docs/计划-APIKey会话共享与远程Codex任务.md（P0 协议和安全基线）**
**依据实现：`server/src/api/auth.ts`、`server/src/api/server.ts`、`server/src/api/policy.ts`、`server/src/ai/secrets.ts`、`server/src/ai/openaiCompat.ts`**

本文档描述当前已实现的保护机制与已知残余风险，只记录代码中真实存在的行为。

## 1. 资产清单

| 资产 | 存储位置 | 说明 |
|---|---|---|
| 模型 API Key | 服务器数据目录 `secrets.json`（文件权限 0600，Windows 上 chmod 可能无效） | 最高价值资产；数据库中只存引用 `apiKeyRef` |
| refresh token | 客户端（Android Keystore，P4）；服务器只存 sha256 哈希 | 48 字节随机值，30 天有效，可轮换/撤销 |
| access token | 客户端内存；服务器内存 Map（不落盘） | 15 分钟短期有效，重启即失效 |
| 设备标识 | `devices` 表 | 设备 id/名称/撤销状态，用于成员与审计 |
| 项目代码 / 任务内容 | 服务器 SQLite + 项目工作目录 | 任务输入、工具调用参数（已脱敏）、事件流 |

## 2. 信任边界

1. **手机 ↔ 服务器**：仅允许 SSH 隧道、Tailscale/VPN 或 HTTPS；服务器默认只监听 `127.0.0.1`，不通过公网端口直接暴露任务和文件 API。
2. **服务器 ↔ 模型服务商**：HTTPS 出站请求，API Key 只出现在发往服务商的 `Authorization` 头中。
3. **SQLite 本地存储**：信任服务器宿主机的文件系统与操作系统账户；数据库文件本身不加密。

## 3. 威胁表

| 威胁 | 影响 | 已实现的缓解措施 | 残余风险 |
|---|---|---|---|
| refresh token 数据库泄露 | 攻击者冒充设备 | 数据库只存 sha256 哈希（`auth_sessions.refresh_token_hash`），明文不可还原 | 哈希可离线碰撞的空间不可行；但整库泄露仍暴露任务内容 |
| refresh token 传输/客户端泄露 | 长期冒用 | 轮换即旧值失效（哈希替换）；`POST /v1/auth/revoke` 与 `DELETE /v1/auth/devices/:id` 撤销立即生效（每次校验回查撤销状态，并清除内存中对应 access token） | 泄露到被发现之间的窗口期仍可冒用 |
| access token 泄露 | 短期冒用 | 仅 15 分钟有效、仅存内存不落盘；撤销会话/设备时同步失效 | 15 分钟窗口内无法单独吊销单个 access token（只能撤销整个会话） |
| 暴力破解 / 凭据填充 | 未授权绑定或认证 | 限流：绑定 5 次/10 分钟、刷新 60 次/10 分钟、认证失败 30 次/10 分钟（按客户端 IP，固定窗口），超限返回 429 | 固定窗口限流可被低速爆破绕过；无账户锁定机制 |
| API Key 泄露（响应/日志/事件/错误文本） | 模型额度被盗用 | Key 只在绑定时入受保护存储，之后不进入任何响应体、审计事件或 SSE 事件；错误信息经 `redactText` 脱敏；测试断言 Key 不出现在响应与错误中 | 若服务商返回的错误报文本身含 Key，脱敏依赖 redact 覆盖度 |
| 越权访问其他项目 | 代码/任务内容泄露 | 项目级角色矩阵（viewer/operator/reviewer/owner），事件流与 `GET /v1/events` 按授权项目过滤；任务创建校验 `sessionId` 归属 `projectId` | 文件/git/终端/IDE 接口尚未按项目角色细化（窗口期内仅本地管理员可用） |
| 重放/重复提交 | 重复扣费或重复执行 | `X-Client-Request-Id` 幂等键 + 数据库唯一索引去重 | 跨设备并发同键的联调验证待做 |
| 旧静态 Token 泄露 | 完全控制 | 迁移窗口内保留，窗口结束（D-13 废弃条件达成）后移除 legacy 通道 | 窗口期内该 Token 即本地管理员，泄露等于全盘失守 |
| SSE 事件流滥用 | 信息泄露 / 资源耗尽 | 需认证；按授权项目过滤；每设备最多 5 条并发流；15 秒心跳 | 连接上限与心跳未有专项测试 |
| 绑定接口被滥用注册恶意配置 | 消耗模型额度 | 绑定前 `testModelKey` 实测连接并要求模型返回工具调用，失败不落库；绑定限流 | 配对码/管理员确认的增强绑定未实现，仅凭有效 Key 即可注册设备 |

## 4. 已知的未缓解项

- **Windows DPAPI 凭据保护未实现**：`secrets.json` 为普通文件存储（仅尝试 chmod 0600，Windows 上无效），依赖操作系统账户隔离。
- **配对码 / 本地管理员确认增强绑定未实现**：当前持有有效 API Key 即可完成首次绑定（计划文档 4.1 标注的增强项）。
- **SSE 每设备连接上限（5）与心跳（15s）未有专项测试**。
- **文件/git/终端/IDE 接口的项目级角色细化待做**：迁移窗口内一律要求本地管理员 Token。
- **多设备并发相同 `X-Client-Request-Id` 的真实联调未做**（当前由全局幂等键与唯一索引保证）。

## 5. 隐私说明（Key 生命周期）

1. **绑定**：App 提交 `apiKey` 至 `POST /v1/auth/link`，服务器先 `testModelKey` 验证，通过后写入受保护存储（`secrets.json`），数据库只存 `apiKeyRef` 引用；验证失败则 Key 不落库。
2. **使用**：每次模型调用从受保护存储取出 Key，仅用于发往服务商的请求头。
3. **不外泄**：Key 不返回给任何 API 响应、不写入日志/审计事件/错误文本；审计事件只记录设备、角色、动作。
4. **手机端不留存**：绑定成功后手机只保存 refresh token（P4 起存 Android Keystore），不保存 API Key。
5. **删除**：删除模型配置时同步从受保护存储删除对应 Key（`DELETE /v1/models/:id`）；更新 Key 走 `POST /v1/models/:id/key` 覆盖存储。
