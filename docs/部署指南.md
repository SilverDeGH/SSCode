# 部署指南

**版本：V0.1** · **编制日期：2026-09-30**
**对应决策：D-11（Windows 直连）、D-13（旧客户端兼容窗口）、D-14（数据库迁移与回滚）**

本文覆盖 sscode-server 的部署约束、连接方式、升级与回滚。首次安装的逐步操作（OpenSSH、防火墙、Node.js、自启动）见根目录 [README.md](../README.md)，本文不重复。

## 1. 硬性约束：不暴露公网

- sscode-server **只监听 127.0.0.1**（默认 7823，`server.listen(port, '127.0.0.1')`），不直接接受局域网或公网连接。
- 禁止通过端口转发、反向代理或防火墙放行把任务和文件 API 暴露到公网（计划文档 §7 明确禁止）。
- 服务器自身不提供 HTTPS 监听，也不支持公网暴露；远程访问只允许下面三种受控传输。

## 2. 支持的三种连接方式

### 2.1 SSH 隧道（基础方式）

手机经 SSH 登录电脑（Windows 账户密码或私钥），在隧道内访问 127.0.0.1:7823。SSH 提供加密与主机指纹校验；Windows 上由 OpenSSH Server 提供，安装、防火墙与私钥配置见根 README 第 3 节。

### 2.2 Tailscale / VPN（推荐跨网络）

Tailscale 为手机和电脑分配虚拟网络地址（通常 `100.x.x.x`），在校园网、热点、移动网络下仍可互通。SSH 隧道建立在 Tailscale 地址之上：App 主机地址填电脑的 Tailscale IP，电脑防火墙放行手机的 Tailscale IP 访问 TCP 22。Tailscale 登录不替代 Windows SSH 认证，也不需要启用 Tailscale SSH 功能。

### 2.3 同一局域网 / 手机热点直连

手机和电脑处于允许设备互访的同一局域网（或电脑连接手机热点）时，App 主机地址填电脑的局域网 IPv4，其余仍走 SSH。换 Wi-Fi 或热点后地址可能变化，需要重新填写。

三种方式下手机到 7823 的流量都封装在 SSH 隧道内；区别只在 SSH 连接经过哪张网络。

## 3. 数据目录与凭据

数据目录：`%USERPROFILE%\.sscode`（Windows）/ `~/.sscode`（Linux），可用 `SSCODE_DATA_DIR` 覆盖。

| 文件 | 内容 | 保护 |
|---|---|---|
| `sscode.db` | SQLite：项目、会话、任务、事件、设备、成员、refresh token 哈希（只存哈希，明文不可还原） | 依赖操作系统账户隔离，文件本身不加密 |
| `secrets.json` | 模型 API Key（数据库只存 `apiKeyRef` 引用） | 写入时尝试 0600 权限；Windows 上 chmod 可能无效，DPAPI 保护未实现（残余风险，见 [隐私与威胁模型](隐私与威胁模型.md) 第 4 节） |
| `auth-token` | 旧静态访问令牌（本地管理员） | 启动时写入并打印到 stdout，分享启动日志前注意遮蔽 |

不要把该目录共享给其他 Windows 用户，也不要把其中任何文件发到公开渠道。服务应以日常使用 SSH 登录的同一个普通用户运行，不要用 SYSTEM 或另一个管理员账户，否则数据目录与 App 读取令牌的目录不一致。

## 4. 升级与回滚（D-14）

数据库采用版本化迁移：启动时按 `kv_meta.schema_version` 逐版本顺序执行（当前 `SCHEMA_VERSION=4`，v4 新增任务/审批的发起设备字段，`server/src/db/schema.ts`），每个版本在独立事务内执行，失败回滚该版本并中止启动。**没有自动整库回滚机制**，回滚靠人工备份恢复。

升级步骤：

1. 等待当前 AI 任务结束、保存文件。重启服务会使非终态任务转为 `interrupted`、Windows 终端会话丢失；所有设备的 access token 失效（仅存内存），App 会自动用 refresh token 换新，**无需重新绑定**。
2. **手工备份数据库**：服务停止后复制 `%USERPROFILE%\.sscode\sscode.db` 到安全位置。
3. 替换 `server` 目录文件，用 `server/scripts/start-windows.ps1` 重新启动。
4. 检查 `GET /v1/health`：版本号符合预期，`capabilities` 应包含 `session-auth`、`event-stream`。
5. 手机侧覆盖安装相同签名、更高 versionCode 的 APK。**只升级 APK 不会更新电脑上已运行的服务。**

回滚（升级失败时）：

1. 停止服务。
2. 用升级前备份的 `sscode.db` 覆盖数据目录中的同名文件。
3. 换回旧版本 `server` 文件并重启。

## 5. 迁移窗口注意事项（D-13）

- 旧静态 Token 在迁移窗口内保留，认证时视为本地管理员（`kind=legacy`，全项目 owner）。窗口期内该 Token 泄露等于全盘失守，应像保管密码一样保管 `auth-token` 文件和启动日志。
- 文件、Git、终端、完整 IDE 等宿主能力接口在窗口期内**仅接受旧静态 Token**；设备会话 Token 访问这些接口返回 403。WebSocket 终端维持旧 Token 认证（Authorization 头或 `?token=` 查询参数）。
- 设备会话流程（`POST /v1/auth/link` 绑定）在窗口期内与旧流程并存：首台绑定设备成为所有现有项目的 owner，之后绑定的设备默认 viewer，由 owner 在项目成员管理中提升角色。
- 废弃条件：Android 端完成会话绑定迁移、旧客户端完成升级后移除 legacy 通道，宿主能力接口届时改为按项目角色鉴权。
